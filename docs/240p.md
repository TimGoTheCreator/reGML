# 240p builds

Add `-DREGML_240P=ON` to the CMake configure command for any platform. It defaults to `OFF`.

```sh
cmake -S . -B build/240p -DCMAKE_BUILD_TYPE=Release -DREGML_240P=ON
cmake --build build/240p
```

For Wii or Wii U, use the usual devkitPro toolchain and platform options, with the same `REGML_240P` flag added.

The main screen renders at 320x240 instead of 640x480. Game coordinates, room dimensions, input, and timing stay unchanged. Sprite and primitive positions scale at the renderer boundary. Screenshots contain the smaller frame.

Desktop and Wii U upload the smaller software canvas. Wii draws into a smaller GX viewport, copies it to a texture, then expands it for display. This changes the internal rendering resolution; it does not switch the console's output signal to native 240p.

Surfaces and source textures retain their original resolutions. This reduces main-screen pixel work and framebuffer memory, but does not quarter the whole game's RAM use or VM workload. Software minification selects an original source color, favoring visible strokes instead of averaging colors. This retains thin lines and keeps menus sharp, but can thicken bright details. GX uses linear texture minification. Small text still loses detail at the lower resolution; presentation scales the finished frame without smoothing.
