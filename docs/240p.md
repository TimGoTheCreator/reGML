# 240p builds

Add `-DREGML_240P=ON` to the CMake configure command for any platform, defaults to `OFF`

```sh
cmake -S . -B build/240p -DCMAKE_BUILD_TYPE=Release -DREGML_240P=ON
cmake --build build/240p
```

For Wii or Wii U, use the usual devkitPro toolchain and platform options, with the same `REGML_240P` flag added

Main screen renders at 320x240 instead of 640x480
Game coordinates, room dimensions, input and timing stay the same
Sprite and primitive positions scale at the renderer boundary
Screenshots have the smaller frame

Desktop and Wii U upload the smaller software canvas
Wii draws into a smaller GX viewport, copies it to a texture, then expands it for display
Internal render size changes, console output signal is not native 240p

Surfaces and source textures keep their original resolutions
This cuts main-screen pixel work and framebuffer memory, but not the game's RAM use or VM work by a quarter
Software minification picks a source color instead of averaging, keeps thin lines and menus sharp, but can thicken bright details
GX uses linear texture minification
Small text still loses detail at the lower resolution, the finished frame scales without smoothing
